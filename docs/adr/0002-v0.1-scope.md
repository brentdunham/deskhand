# ADR 0002: v0.1 Scope

- Status: Accepted
- Date: 2026-10-29

## Context

v0.1 goes to a small group of testers. Its purpose is to prove one complete loop: the user summons DeskHand, asks for something, the agent acts under policy, and the user reviews and undoes what it did. Breadth is deferred.

## Decision

### In scope

1. **Summon surface.** A global hotkey toggles a floating, always-on-top panel. Tray icon with quit and settings. Default hotkey `Ctrl+Alt+D`, configurable. (`Win+Space` and `Alt+Space` collide with input switching and PowerToys Run; `Ctrl+Alt+Space`, the original default, collided with other desktop AI apps in testing.)
2. **Providers.** Anthropic, plus one OpenAI-compatible endpoint (covers Ollama). Keys stored in Windows Credential Manager. Model picker. Streaming responses.
3. **Read-tier tools.** List windows and monitors; read the active window's text via UI Automation; read the clipboard; search files under user-chosen folders; list installed apps from Start menu shortcuts.
4. **Reversible-tier tools.** Focus, move, resize, snap, and minimize windows; launch apps; open files, folders, and URLs; write the clipboard; create folders; move or rename files; delete to the Recycle Bin only.
5. **Named layouts.** Save the current window layout under a name and restore it.
6. **Policy engine.** Three tiers (read, reversible, irreversible). User overrides can only tighten policy (`ask`, `deny`); there is no "always allow". Irreversible tools always require confirmation. While untrusted content (screen, clipboard, file, web, or tool output) is in the model context, taint-sensitive tools require confirmation.
7. **Action log.** A panel listing every tool call with arguments, gate result, tier, and outcome, with undo for reversible actions.
8. **Config.** TOML in the app data directory: hotkey, providers, search roots, layouts, per-tool overrides. Hot reload.
9. **Distribution.** Signed NSIS installer and a Chocolatey package.

### Deferred to v0.2 or later

- Shell execution (PowerShell). It needs its own allowlist design.
- MCP: exposing DeskHand tools to other agents and consuming external servers.
- Docked AppBar sidebar, routines and scheduled tasks, voice, screenshot and vision fallback, learned preferences, shell-replacement mode.

### Exit criteria

- A tester installs with `choco install deskhand`, adds a key, and completes a scripted task set without help: arrange windows, find and open a file, summarize the active window, save and restore a layout.
- No irreversible action executes without confirmation, verified by tests in `deskhand-policy`.
- Works on Windows 11 and Windows 10 22H2.

## Consequences

- The feature list originally included a per-tool "always allow" override. It was removed because it contradicts the exit criterion on irreversible actions.
- Build order: `deskhand-policy` (done), window tools in `deskhand-win`, the tool layer in `deskhand-tools`, the agent loop in `deskhand-agent`, then UI panels.
